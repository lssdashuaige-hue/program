# PAS-020 — Integration & First Working Prototype

**中文名：** 全系统整合与第一个可运行原型
**版本：** 0.1

## 原型目标

第一次将认证、前端、后端、AI、安全、记忆和数据库连接为可验证的用户闭环。

## 完整流程

```text
用户注册
→ 阅读边界和设置记忆偏好
→ 创建探索会话
→ 发送体验
→ 输入风险检测
→ 检索相关确认记忆
→ 生成并审核 PAS 回应
→ 保存消息
→ 提出候选记忆
→ 用户确认或拒绝
→ 更新历史和心理地图
```

## API 基线

- `GET /health`
- `POST /chat`
- `GET /conversations`
- `GET /conversations/{id}/messages`
- `GET /memories`
- `POST /memories/{id}/confirm`
- `PATCH /memories/{id}`
- `DELETE /memories/{id}`
- `GET /themes`
- `GET /export`
- `DELETE /account`

最终路由可调整，但资源所有权和行为边界不得削弱。

## 集成要求

- 前端使用认证令牌访问后端；
- 后端验证令牌，不信任客户端传入的 `user_id`；
- 数据库 RLS 作为第二层隔离；
- 模型密钥仅在后端；
- 消息保存和候选记忆更新具备一致性；
- 每次 AI 生成记录模型、Prompt 和安全策略版本；
- 日志不保存完整心理正文。

## 原型简化

- 一个后端服务；
- 规则 + LLM 的风险和候选判断；
- 结构化数据库检索；
- 简单卡片式心理地图；
- 无支付、社区和复杂报告。

## 测试

端到端验证：

1. 新用户注册并完成首次会话；
2. 重新登录后会话仍存在；
3. 未确认候选不进入地图；
4. 确认、修改和删除即时生效；
5. 用户间数据隔离；
6. 高风险输入进入安全模式；
7. 服务失败时安全降级；
8. 删除账户后数据不可访问。

## 完成标准

原型的意义不是证明产品成熟，而是允许小规模真实用户在可控、安全和可观察的条件下开始使用。
