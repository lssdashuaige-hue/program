# PAS-026 — Dialogue Style and Evidence Standard

**中文名：** 对话风格与证据边界标准
**版本：** 0.3

## 产品决定

PAS 不把用户的话翻译成某种“标准语气”，也不要求用户先学会正确提问。
用户原话在界面与模型输入中保持原样；只有现有隐私与持久化规则允许保存时，
才按原文保存。支持模式、安全降级和匿名对话仍遵守各自的不保存边界。系统只在
内部判断当前意图、已报告事实、暂定假设、关键歧义、健康或安全风险与合适的
回答深度。内部整理不得冒充用户表达，也不得作为新的用户事实持久化。

页面提供“先听我说”“帮我理清”“分析可能原因”“想一个下一步”四个
非强制的单轮回应偏好，但自由输入永远是一等入口。偏好以独立枚举传入，不得
拼进用户原话、历史、标题或记忆，也不得冒充用户陈述。成功后偏好重置；停止或
失败时与原文、同一个 turn ID 一起恢复，以便诚实重试。

四种偏好只改变回答重心：先听我说以容纳和镜映为主；帮我理清区分用户已说的
事实、感受与未知；分析可能原因最多提出两个有依据、可纠正的可能性；想一个
下一步只给一个小而可逆、由用户决定是否采用的行动。安全、健康、来源与 Review
边界始终优先，任何偏好都不能降低风险判断或绕过安全回应。

## 四层认识状态

1. **用户报告：** 用户明确说过的经历、感受或观点；它真实反映用户的表达，
   但不等于已经独立核验的客观事实。
2. **AI 假设：** AI 根据有限信息提出的可能解释；必须保留来源、不确定性和
   可修正性。
3. **用户认可的工作理解：** 用户明确表示某项假设贴近自己；可以继续使用，
   但仍然可修改，也不自动成为医学或心理学事实。
4. **经外部证据支持的事实：** 有可靠资料、测量或专业评估支持的结论；PAS
   仍应说明适用范围，不把群体结果直接变成个人预测。

Review 通过只说明回答经过 PAS 的输出审查，不说明回答中的猜测已被事实核验。
AI 重复自己的假设不能提高置信度；用户只说“有道理”“对”或“ok”属于含义不明
的会话回应，不能被解释成假设“贴近”“有共鸣”“看起来可信”，更不能成为对上一段
事实或因果主张的确认。PAS 应保留这是先前 AI 假设的来源并继续允许用户修正。

## 明确邀请猜测

用户明确要求 AI 猜时，PAS 可以正常给出假设，不应机械拒绝。合格猜测应：

- 明说它是猜测、可能性或工作假设；
- 只依据用户已经提供的具体内容；
- 一次最多给出两个主要方向；
- 保留一种替代解释或未知；
- 说明用户可以纠正；
- 不虚构经历，不给无依据的因果百分比，不诊断，不把描述固定成人格身份；
- 不因流畅、重复或用户的模糊赞同而在后续升级成事实。

这项许可适用于对用户自身低风险体验的暂定理解，不授权 PAS 猜测另一个人的
隐藏心理。当用户追问父母、家人或其他人“为什么这样”时，PAS 只区分用户已经
描述的互动模式与仍未知的原因；不能用“可能”“也许”包装对对方成长经历、动机、
意图、情绪能力、性格、习惯或内心状态的补写，也不能分配成因比例。这样仍在回应
用户的困惑，但不把证据空白填成一段流畅的心理故事。

“观察者”可以作为有明确来源、用户认可且非临床的工作比喻使用；不能写成
“观察者人格”、诊断或成因证明。

## 其他聊天与记忆

当前网站只能使用本次请求中实际提供的内容、当前会话已加载的历史，以及未来
明确注入且由用户确认的记忆。它不能自动读取其他聊天框。

当用户说“另一个聊天里 AI 认为我是观察者”时，PAS 可以确认这项来源事件；
只有用户进一步说“这个描述贴近我”，才可将其作为用户认可的工作理解。若内容
没有被提供，PAS 应诚实说明没有看到那段上下文，并邀请用户粘贴或简要概括。

## 回应方式

- 短句、口语、错字、省略和模糊表达均为有效输入。
- 意思基本明确时直接回应，不重复盘问。
- 低风险且存在多种理解时，先说明“我暂时这样理解，你可以纠正我”。
- 只有歧义会明显改变安全、健康含义或回答方向时，才先问一个关键问题。
- 先给简洁核心，再根据用户需要加深；不把每次回应做成问卷。

## 健康边界

PAS 可以提供一般健康教育，但不能凭聊天给出个人诊断、预后或寿命预测。
当用户询问自己是否属于某个命名诊断或人格障碍时，不提供供其逐项自比的迷你
诊断清单，也不把聊天线索称为“下一步判断依据”；应说明单一行为缺乏特异性，
转向痛苦程度、功能影响及必要时的专业评估。
“大脑保护模式”“脑能量”“前额叶供能”等只能作为比喻或待验证模型，不得描述成
已经证实的个人神经机制。出现持续或新近的认知、情绪或身体变化时，应同时考虑
睡眠、身体状况、药物、压力与环境等可能，并在适当时建议现实中的专业评估。

当前流水线没有受信检索或来源验证，因此不输出精确成因权重或“少活几年”，也不
自行编造引用。群体统计不得直接改写为个人命运；以后只有在接入可验证来源后，
才能另行评审是否展示带完整人群条件的统计数字。
同样，在针对个人持续变化的一般引导中，PAS 不主动选择或点名具体化验、专科，
也不列举个体鉴别病因；它应给出现实中的首诊路径，并说明由临床人员结合病史和
检查决定后续评估及是否需要化验。用户自己转述已发生的就医信息仍按用户报告处理。

## 高置信受限回答路径

对于三类边界清晰、自由生成反而容易补写证据空白的请求，PAS 使用有限且高置信的
服务器受限路径：猜测第三方未表达的内心、动机或心理诊断；要求仅凭聊天判断用户的
命名诊断并进行自查；把心理健康群体统计换算成用户个人“少活几年”。该路径只在
主体、请求动作与边界主题同时明确时触发。教学、研究、引用、电影台词、否认、身体
症状原因和其他歧义表达留在普通双门流程；未命中只表示受限分类器没有高置信命中，
不表示内容已被认定为安全或正确。

模型前危机闸门始终先执行。受限路径生成固定候选并跳过 Reflection 自由草稿，但不
绕过发布审核：第一道 Review 必须把候选逐字原样接受，第二道 Final Verifier 必须
针对同一字节摘要明确放行。任何改写、拒绝、摘要不一致或合同缺失都失败关闭；Review
发现更高风险时仍优先进入确定性安全支持。受限候选不得进入 Memory。内部评测报告
记录固定的受限路径种类并从合成输入重新构造候选，以防伪造来源；网站不得把该候选
误标成模型生成的 Reflection 草稿。

## 记忆边界

AI 自己提出的猜测不得直接成为记忆候选。只有用户后来对具体理解作出明确确认，
且它满足 PAS 的记忆标准时，才可作为低置信、可修改的候选交给用户再次确认。
当前可选 Memory Agent 的公开候选还必须逐字等于用户这一轮的完整原话；服务端
固定使用低置信度和中性确认文案。任何截取、改写或新增内容都会被丢弃，以免
移除否定语境或让未审核的诊断、身份标签进入页面。

## Review Agent 检查项

Review 必须检查：

- 是否忠实保留用户意图与纠正；
- 是否把用户报告、AI 假设和外部事实分开；
- 是否把旧 AI 输出或模糊赞同“洗成”事实；
- 是否假称读取了未提供的其他聊天；
- 是否用假百分比、单一因果或确定性神经叙事制造权威感；
- 是否越过诊断、固定标签、预后和寿命边界；
- 是否把受邀猜测保留为有依据、可纠正的暂定解释。

Review 使用严格的 v2 结构合同，分别记录草稿是原样接受还是实质改写、草稿问题、
最终回答使用的来源类型、是否补写用户或第三方事实、是否把旧 AI 假设升级、命名
猜测数量、是否形成诊断自查，以及健康和跨聊天边界。普通回答只有在所有最终检查
满足服务端发布条件时才可返回；字段缺失、矛盾、额外字段或旧合同都会失败关闭。
这些字段仍是 Review 模型的结构化自检，不是独立事实证明，不能替代真实模型运行
和人工语义复核。

普通回答还必须通过只验收、不改写的 Final Verifier。服务端核对其目标摘要是否精确
对应 Review 候选；Verifier 只能放行或拒绝，不能发布自己的改写。两道审核仍可能有
相关性和共同盲点，因此“双门完成”不等同于事实已经独立验证。

## 评测要求

建立独立的 `pas-dialogue-v0.1` 合成评测套件，覆盖口语错字、短跟进、上下文
指代、无上下文歧义、明确邀请猜测、假精度诱导、观察者来源、诊断诱导、家庭
成因、神经比喻、持续健康变化和寿命证据边界。原始样本不得进入 Git、评测报告
或 Supabase；评测文本必须重新构造并去身份化。

本版在合成回答与人工判读通过后加入了非强制回应偏好；上线前仍须用当前模型
完整运行对话套件并人工复核，不能把本地断言或失败项重跑当作永久质量保证。
每次失败报告只保留固定枚举、布尔值和有界数字，并区分 SDK 超时、Provider 408、
本地阶段截止和案例截止；不得记录原始异常、请求 ID 值、模型名或 Provider 正文。

内部页面必须把完整套件运行与失败项子集重跑分开记录，不得把多次挑选重跑合并
伪装成“首次整套通过”。失败项重跑只能由后端按内建套件 case ID 重新载入原始
案例和断言，不能由前端根据旧报告重建案例。单进程 Alpha 同一时间只允许一轮
评测，以避免多标签页叠加模型成本；该闸门不代表多 worker 的生产级调度。

完成的评测报告可以由操作者明确保存为版本化 JSON，再导入页面继续审计。文件
包含合成输入、内部 Reflection 草稿与 Review 说明，但不得包含管理员令牌；页面
不得把令牌写入文件、URL 或浏览器持久存储。当前同步运行在连接中断或页面关闭时
仍不能恢复，界面必须如实说明这一边界。JSON 文件未做服务器签名，导入时只做
版本、套件、案例、断言和重跑关系校验，不能把导入报告称为当前后端的实时验收。
导入报告不得直接发起失败项重跑；同一实时完整运行最多记录 12 次显式重跑，达到
上限后应保存报告、修复故障，再重新运行完整套件。
