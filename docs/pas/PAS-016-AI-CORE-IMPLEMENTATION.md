# PAS-016 — AI Core Implementation

**中文名：** PAS 核心 AI 引擎实现
**版本：** 0.1

## 目标

将 PAS 的交互哲学转化为可测试的 AI 管线。重点不是让模型显得更专业，而是稳定地产生尊重用户、促进探索并符合安全边界的回应。

## 处理流程

```text
用户消息
→ 输入风险分类
→ 当前会话上下文
→ 相关已确认记忆
→ 探索方向规划
→ 模型生成草稿
→ 边界与危机输出检查
→ 最终回应
→ 候选记忆判断
```

## Context Builder

上下文仅包含：

- 当前消息；
- 最近必要对话；
- 当前探索主题；
- 少量相关且允许使用的确认记忆；
- 当前安全模式；
- Prompt 版本。

不得把全部历史或未确认推断发送给模型。

## Exploration Planner

内部结构化输出可包含：

- 可观察事实；
- 可能情绪；
- 自动想法；
- 行为与关系线索；
- 合理替代假设；
- 需要确认的内容；
- 最合适的下一步问题。

这些是对话规划，不直接作为用户画像保存。

## Prompt 分层

- Identity：AI 的角色和非医疗定位；
- Reflection：镜像、探索和整合方法；
- Memory：历史只能作为可修正参考；
- Safety：危机、诊断、依赖和现实边界；
- Output schema：结构化结果和错误处理。

Prompt 必须独立版本管理，记录变更原因和评测结果。

## 回应要求

- 先理解用户原话；
- 避免每次固定模板；
- 一次优先一个核心探索问题；
- 使用日常语言；
- 假设明确保持不确定；
- 用户表达与历史冲突时以当前表达为准；
- 安全风险出现时立即切换模式。

## 记忆输出

模型只能提出候选记忆：

```json
{
  "candidate": true,
  "type": "reflection",
  "content": "用户注意到……",
  "confidence": "low",
  "requires_confirmation": true
}
```

后端必须再次验证，用户确认后才能成为持久记忆。

## 测试

评测集至少覆盖失败、自我否定、关系冲突、绝对化判断、依赖表达、现实判断困难、自伤风险和普通日常探索。
