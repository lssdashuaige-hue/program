# PAS-023 — Data Privacy & Trust Architecture

**中文名：** 数据隐私与信任架构
**版本：** 0.1

## 信任原则

用户拥有自己的心理数据。PAS 只是获得有限授权来提供服务。用户始终拥有查看、修正、删除、导出、暂停和撤回授权的能力。

## 数据分级

- Level 0：公开产品内容；
- Level 1：账户和基础设置；
- Level 2：对话内容；
- Level 3：心理模型、记忆与总结；
- Level 4：危机相关数据。

等级越高，访问范围、保留时间、日志策略和人工访问要求越严格。

## 数据最小化

- 默认只收集提供服务所必需的数据；
- 不保存内部思维链；
- 日志使用请求 ID、延迟、模型版本和安全结果；
- 不在分析系统复制对话正文；
- 候选记忆必须获得用户确认；
- 危机信息不因“可能有价值”而无限期保存。

## 安全控制

- 全程 TLS；
- 数据库静态加密由托管平台提供；
- 高敏感字段可增加应用层加密；
- 环境变量和秘密管理；
- Supabase RLS 与后端授权双重隔离；
- 管理操作审计；
- 定期备份和恢复测试；
- 最小权限与密钥轮换。

## AI 数据政策

默认不使用用户内容训练或改进通用模型。任何研究或训练用途必须：

1. 单独、清楚、可撤回的主动同意；
2. 说明用途、处理者、保留期和风险；
3. 去标识化和最小化；
4. 不因拒绝而降低核心安全服务；
5. 支持删除和退出。

## 用户控制中心

展示：

- 保存的数据类别和数量；
- 每条记忆的来源、状态和用途；
- 当前同意设置；
- 导出和删除进度；
- 账户删除的范围与预计完成时间。

删除必须覆盖主库、索引、embedding 和可控缓存；备份中的残留按明确周期过期。

## 企业边界

企业客户不能访问个人内容。聚合洞察必须设置最小群体阈值，禁止用于招聘、绩效、纪律、保险或个体风险评分。

## 信任定义

> 信任不来自一段“我们重视隐私”的声明，而来自用户能够看见系统保存什么、为什么保存，并能真正改变或删除它。
