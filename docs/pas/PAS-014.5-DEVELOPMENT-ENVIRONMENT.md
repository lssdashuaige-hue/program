# PAS-014.5 — Development Environment Setup

**中文名：** 开发环境配置方案
**版本：** 0.1

## 目标

在实际编码前建立清晰、低成本且可替换的开发与部署环境。每个平台只承担最适合的职责，Alpha 阶段不提前引入复杂云基础设施。

## 服务分工

```text
GitHub      → 源码、分支、提交和审查
Vercel      → Next.js 前端 Preview 与 Production
Render      → FastAPI 后端服务
Supabase    → PostgreSQL、Auth 和后续向量能力
Cloudflare  → 域名、DNS、TLS 和基础防护
OpenAI API  → 可替换的模型能力
```

Cloudflare Alpha 阶段使用 Free 方案，不使用 Workers、D1 或 Vectorize。只有出现明确性能、安全或部署收益时才重新评估。

## GitHub

- 仓库：`lssdashuaige-hue/program`；
- 默认分支：`main`；
- 功能开发使用独立分支和 Pull Request；
- 环境变量、虚拟环境、依赖目录和 `work/` 不提交；
- `docs/pas/` 是产品与工程决策的正式依据。

## Vercel

- Framework：Next.js；
- Root directory：`frontend`；
- Preview 部署用于分支验证；
- `NEXT_PUBLIC_` 变量只能包含可公开内容；
- 后端 API URL 按 Preview 和 Production 分开配置。

## Render

- Root directory：`backend`；
- 启动 FastAPI 并监听平台提供的端口；
- 保存模型密钥和服务端配置；
- 健康检查指向 `/health`；
- 日志不得输出心理正文或秘密。

## Supabase

- 主地区优先新加坡 `ap-southeast-1`，适合早期亚洲用户和相邻部署；
- 地区选择应考虑主要用户、后端位置、延迟、数据驻留和后续迁移成本；
- 创建项目前确认组织、地区和费用；
- 所有公开用户数据表启用 RLS；
- 前端只使用 publishable key，服务端秘密不得暴露。

当前账号已达到两个活跃免费项目的限制，因此 PAS 项目创建暂停。

## Cloudflare

初期仅配置：

- 域名与 DNS；
- HTTPS；
- 基础 DDoS 和 Bot 防护。

域名购买、DNS 切换和生产发布属于外部变更，必须获得用户明确确认。

## 本地环境

- Windows PowerShell；
- Node.js + `npm.cmd`；
- Python 虚拟环境；
- Git 与 GitHub CLI；
- `.env.example` 记录变量名称；
- 真实 `.env` 永远忽略。

## 分支与发布

```text
main
└── agent/<description>
    → local checks
    → push
    → draft pull request
    → review
    → merge
    → preview/production deployment
```

## 完成标准

- 本地前后端可运行；
- GitHub 身份与远程仓库可验证；
- 云资源状态清楚记录；
- 没有秘密进入 Git；
- 每个部署平台的职责、目录和环境变量边界明确。
