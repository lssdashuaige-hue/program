# PAS-009 — MVP Product Design & Development Roadmap

**中文名：** 第一版产品设计与开发路线
**版本：** 0.1

## MVP 要验证的问题

1. 用户是否愿意进行连续而非一次性的自我探索；
2. 镜像式交互是否比普通建议式聊天产生更多自我理解；
3. 用户是否感觉系统理解的是自己而不是模板；
4. 记忆是否真正延续探索且没有固定用户。

## Alpha 范围

必须具备：

- 账户与隐私说明；
- Reflection Room；
- PAS 基础 Prompt；
- 会话保存；
- 用户确认后形成的基础记忆；
- 探索历史；
- 阶段性反思总结；
- 简单心理地图；
- 基础风险与输出边界检查；
- 数据查看、删除和关闭记忆。

暂不包含：

- 心理诊断与测评；
- 自动人格报告；
- 社区；
- 原生移动应用；
- 大规模游戏化打卡；
- 复杂向量记忆；
- 自训练模型；
- 支付系统。

## 开发阶段

### Phase 1 — 工程骨架

建立前端、后端、数据库迁移、健康检查、GitHub 和部署配置。

### Phase 2 — 核心对话

完成 Reflection Room、后端聊天接口、PAS Prompt 和基础安全。

### Phase 3 — 连续性

加入认证、会话历史、候选记忆与用户确认。

### Phase 4 — 用户理解

加入心理地图、总结、修正和数据控制。

### Phase 5 — Alpha 验证

邀请 20～50 名合适用户进行结构化测试，建立失败案例库。

## 成功信号

关键指标不是消息数量，而是：

- 用户产生新的自我理解；
- 用户认为镜像准确；
- 用户可以纠正系统；
- 用户把理解连接到现实；
- 用户没有感到被诊断、操控或依赖诱导。

典型价值时刻：

> 我以前认为自己只是懒，现在发现我可能常在害怕失败时开始拖延。

## 停止条件

如果基础安全、隐私控制、错误记忆修正或用户身份隔离尚未可靠，不进入公开测试。
